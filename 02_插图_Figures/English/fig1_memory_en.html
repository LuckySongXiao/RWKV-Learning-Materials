How to choose among three "memory methods"?
Language models need to read and remember simultaneously—metaphors and costs of three architectures

Transformer

Passing notes in class
When recalling the 1st word,The current word sends a note to every previous word,waits for replies, then tallies votes. More words = more notes.
Pros

Training can be done in parallel by the whole class, seeing everything comprehensively

Cons

During inference, number of notes ≈ words²: double sequence length, quadruple overhead; must keep all notes, memory keeps growing

Traditional RNN

Single person passing a message
Only one messenger with a small cheat sheet (hidden state): after hearing each word, theymodify the cheat sheetand pass it to the next version of themselves.
Pros

Fixed cheat sheet size: inference memory is constant, doesn't grow with length

Cons

Training must be done sequentially one after another; cheat sheet gets overwritten repeatedly, distant words are easily forgotten

RWKV

The messenger who keeps accounts
Still the messenger modifying the cheat sheet, but it upgrades totwo account books(numerator + denominator), with a carefully designed accounting formula that can also discount old memories.
Pros

Training like Transformer's full class parallelism; inference like RNN's single account book everywhere (constant memory)

Pros

Computation grows linearly with length O(Td), memory constant O(d)

RWKV's goal: have the best of both worlds— Train as fast as Transformer, infer as efficiently as RNN
